# env-preflight: 착수 전 환경 실측

설계로는 예측되지 않고 명령을 돌려야만 드러나는 문제가 있다. 저장소 루트가 생각과 다른 곳에 있거나, 컨테이너 빌드 도구가 root로 돌아 캐시가 root 소유가 되거나, 쓰려던 포트가 이미 점유돼 있는 경우다. 늦게 발견할수록 되돌리기 비싸고, 어떤 것은 산출물 자체를 오염시킨다.

**하네스에서 가장 먼저 실행할 것은 요구사항 인터뷰가 아니라 환경 실측이다.** 계약을 아무리 잘 정해도 환경이 다르면 무효다.

## 언제 쓰는가

- 새 작업을 시작할 때, `spec-interview` 전에
- `plan-execute`, `codex-handoff`가 착수 직전에 오늘 날짜의 preflight 리포트가 없을 때 호출한다
- 런타임, 컨테이너 구성, 접속 대상이 바뀌었을 때

## 원칙

- **측정만 한다. 고치지 않는다.** 설치, 버전 전환, 프로세스 종료, 파일 삭제, 설정 변경은 하지 않는다. 고쳐야 할 것은 보고서에 적고 사람에게 묻는다
- **읽기 전용 명령만 쓴다.** 버전 조회, 포트 조회, 접속 확인(`SELECT 1` 수준), 환경 변수 존재 여부
- **비밀 값을 출력하지 않는다.** 환경 변수는 존재 여부와 길이만 적는다. 값을 리포트에 쓰지 않는다
- 확인할 수 없는 항목은 ✅로 쓰지 않는다. 🔍와 이유를 쓴다

## 기대값 출처

무엇이 "맞는" 환경인지는 아래에서 읽는다. 순서대로 찾고, 찾은 출처를 리포트에 적는다.

1. spec이나 plan에 적힌 런타임, 포트, 접속 대상
2. 빌드 설정 파일(`build.gradle`, `pom.xml`, `package.json`의 `engines`, `.nvmrc`, `.java-version`, `.tool-versions`, `go.mod`, `pyproject.toml` 등)
3. `docker-compose.yml`, `.env.example`, 애플리케이션 설정 파일(`application.yml` 등)의 포트와 접속 주소
4. README의 실행 방법

출처가 없는 항목은 기대값 칸을 "출처 없음"으로 두고 실측값만 적는다.

## 점검 항목

| # | 항목 | 확인 방법 예 | ❌ 조건 |
|---|---|---|---|
| E1 | 저장소 루트 | `pwd`, `git rev-parse --show-toplevel` | 저장소 루트가 작업 디렉터리의 상위(특히 홈 디렉터리)다. 캐시, 도구 설정, 다른 프로젝트가 산출물에 섞인다 |
| E2 | 무시 규칙 | `.gitignore` 존재 여부, `git status --short --ignored` 로 빌드 산출물과 캐시가 무시되는지 | 빌드 산출물이나 캐시 디렉터리가 미추적으로 잡힌다 |
| E3 | 덮어쓸 파일 | 플랜이나 spec이 만들 파일 이름(README, 설정 파일 등)이 이미 있는지 | 기존 파일과 이름이 겹치는데 그 파일이 다른 용도다(예: 요구사항 원문이 README에 들어 있음). 백업이나 이름 변경 결정이 필요하다 |
| E4 | 런타임 버전 | `java -version`, `node -v`, `python3 --version`, `go version` 등 | 기대값과 메이저 버전이 다르다 |
| E5 | 빌드 도구 | `./gradlew --version`, `mvn -v`, 패키지 매니저 버전, 래퍼 실행 권한 | 실행 불가, 래퍼 없음, 기대 버전과 다름 |
| E6 | 컨테이너 | `docker info`, compose 파일의 `user:` 설정, 빌드 도구 컨테이너가 root로 도는지 | 데몬 미기동. 또는 빌드 도구 컨테이너가 root로 돌아 호스트 쪽 캐시와 산출물이 root 소유가 될 구성이다(named volume이나 `--user` 지정 필요) |
| E7 | DB 접속 | 설정의 접속 주소로 `SELECT 1` 수준 확인, 또는 포트 연결 확인 | 접속 불가, 스키마 없음 |
| E8 | 메시지 브로커 등 외부 의존 | 설정의 접속 주소로 연결 확인 | 접속 불가 |
| E9 | 포트 | 쓸 포트마다 `lsof -nP -iTCP:<포트> -sTCP:LISTEN` 또는 `ss -ltnp` | 이미 다른 프로세스가 점유. 점유 프로세스 이름을 적는다 |
| E10 | 필수 환경 변수 | `.env.example`이나 설정 파일의 `${...}` 참조 목록과 현재 셸 대조. 값은 출력하지 않고 존재 여부만 | 필수 변수가 비어 있다 |
| E11 | 작업 트리 상태 | `git status --short` | 착수 전 정리되지 않은 변경이 있다(이후 diff로 변경을 분리할 수 없다) |
| E12 | 격리 도구 | 플랜이 브랜치나 worktree 격리를 쓰기로 했으면 `git worktree list`와 생성 가능 여부 | 그 환경에서 worktree를 만들 수 없다 |

해당 없는 항목(DB가 없는 프로젝트 등)은 "해당 없음, 이유"로 적는다. 조용히 빼지 않는다.

## 산출물

경로: `<repo>/.claude/harness/report/preflight-<slug>-<YYYYMMDD>.md`. 같은 날 다시 돌리면 덮어쓴다. 디렉터리가 없으면 만든다.

```markdown
# env-preflight: <slug> (YYYY-MM-DD HH:MM)

기대값 출처: <파일 경로 나열>

| # | 항목 | 기대값 | 실측값 | 상태 | 조치 제안 |
|---|---|---|---|---|---|
| E1 | 저장소 루트 | 작업 디렉터리와 같음 | <경로> | ✅ / ❌ / 🔍 / 해당 없음 | |
| E4 | 런타임 | Java 21 | 21.0.4 | ✅ | |
| E9 | 포트 8080 | 비어 있음 | <프로세스 이름>이 점유 | ❌ | 점유 프로세스 종료 또는 포트 변경 결정 필요 |

## 판정: ✅ 착수 가능 / ⚠️ 조건부 / ❌ 착수 불가

## 사람이 결정할 것
- <❌, ⚠️ 항목마다 한 줄. 선택지 2개 이상>
```

판정 기준:

| 조건 | 판정 |
|---|---|
| ❌ 0건 | ✅ 착수 가능 |
| ❌는 없고 🔍만 있다 | ⚠️ 조건부. 🔍 항목을 사람이 확인하면 착수 |
| E1, E3, E6, E11 중 하나라도 ❌ | ❌ 착수 불가. 산출물 오염이나 되돌리기 비싼 부작용으로 이어진다 |
| 그 밖의 ❌ | ❌ 착수 불가. 단 사람이 "알고 진행"을 택하면 리포트의 그 행에 사람의 결정을 적고 ⚠️로 바꾼다 |

## 다음 단계

- ✅면 호출한 쪽(`spec-interview`, `plan-execute`, `codex-handoff`)으로 돌아간다
- ⚠️, ❌면 멈추고 `사람이 결정할 것`을 보여 준다. 환경을 고치는 일은 사람이 하거나, 사람이 지시한 뒤에 한다
- 실측값 중 플랜 전제와 다른 것이 있으면(예: 런타임 버전) plan-build나 plan-verify가 전제 표에 반영하도록 보고에 적는다

## Completion Criteria

- 리포트가 `<repo>/.claude/harness/report/preflight-<slug>-<YYYYMMDD>.md`에 있다
- E1~E12 모든 행에 상태가 있고, 해당 없는 행에는 이유가 있다
- 리포트에 비밀 값이 없다
- 판정 줄이 하나 있다
- 환경을 바꾸는 명령을 실행하지 않았다
