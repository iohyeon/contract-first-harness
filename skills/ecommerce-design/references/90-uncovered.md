# 미검증 영역

## 커버리지 공백 목록 (아는 척 금지)

아래 주제는 학습하지 않았고 카드에도 규칙이 없다. 요청이 여기 해당하면 **먼저 "이 부분은 검증된 규칙이 없다"고 밝히고**, 일반론 수준으로만 다루거나 사용자에게 결정을 받는다.

| 주제 | 비고 |
|---|---|
| 매장 재고 기반 즉시배송, 픽업 | 다중 출고지 중 매장을 재고 원천으로 쓰는 구조. 01 카드에는 "창고가 여럿이면 사이트별로 나뉜다" 수준만 있다 |
| 출고지 할당 알고리즘 | 거리, 재고량, 비용 중 무엇을 우선할지 판단 규칙 없음 |
| 정기결제, 빌링키, 구독 | 승인과 매입 구조는 적용되지만 빌링키 보관, 주기 실패 재시도, 구독 상태기계는 미학습 |
| 후불결제, 할부, 해외결제, 다통화 | 취소 정책과 환율 반영 규칙 없음 |
| 세금계산서, 현금영수증, 부가세 처리 | 법령 확인 필요 영역 |
| 배송비 정책 전반 | 무료배송 기준, 조건부 배송비, 반품 배송비 계산 |
| 재고 실사와 조정 | 실물과 장부 불일치 보정 절차 |
| 셀러 스코어링, 페널티 제도 | 존재 이유는 확인됐으나 설계 규칙은 없음 |
| 검색, 랭킹, 추천 | 학습 범위 밖 |

## 도메인 개괄 (클레임, 풀필먼트, 정산)

이 영역은 학습 노트가 아직 없다. 도메인 지도 수준의 개괄만 존재한다.
**여기 적힌 내용을 확정 규칙처럼 서술하지 않는다.** 일반적인 고려사항으로 제시하고, 사용자에게 결정을 받거나 별도 확인이 필요하다고 명시한다.

---

## 클레임 (취소, 반품, 교환)

같은 "취소"라도 시점에 따라 완전히 다른 처리가 된다.

| 발생 시점 | 돈 | 물건 | 정산 |
|---|---|---|---|
| 결제 직후 (출고 전) | 승인 취소 | 선점 해제 | 발생 안 함 |
| 출고 후 배송 중 | 승인 취소 또는 환불 | 회수 필요 | 발생 안 함 |
| 인도 후 마감 전 | 환불 | 회수, 검수, 재입고 또는 폐기 | 당기 차감 |
| 인도 후 마감 후 | 환불 | 회수, 검수 | 차기 조정 |

미결 질문.

- 클레임을 주문의 하위 상태로 볼 것인가 독립 애그리거트로 볼 것인가
- 부분 반품 시 할인 안분 결과를 어떻게 적용할 것인가
- 귀책(고객 변심, 상품 하자, 오배송)에 따라 회수 배송비를 누가 부담하는가
- 회수 물품 검수 결과에 따른 분기(재입고, 반품 거부, 폐기)

## 풀필먼트와 배송

물건이 실제로 움직이는 구간. 실물재고가 감소하는 지점이 여기다.

구성 요소: 입고, 보관, 출고지 할당, 피킹, 패킹, 송장 발급, 배송사 연동, 추적, 회수.

미결 질문.

- 창고가 여럿일 때 어느 출고지에서 뽑을 것인가 (거리, 재고량, 비용)
- 한 주문의 품목이 여러 창고에 흩어져 있으면 분할 출고인가 이고인가
- 배송사 상태 코드를 자사 상태로 어떻게 매핑할 것인가
- 통지 유실 시 추적 상태를 어떻게 복구할 것인가

경계 원칙 하나는 확인됐다. **물류는 금액을 알 필요가 없다.** 출고 지시에 금액 정보를 넘기지 않는다.

## 정산과 대사

앞의 모든 도메인 결과가 금액으로 모이는 구간.

구성 요소: 수수료 구조, 정산 주기와 마감, 대사, 원장, 지급.

판매 형태에 따라 구조가 갈린다.

| 형태 | 매출 인식 | 정산 |
|---|---|---|
| 1P 직매입 | 판매가 전액 | 공급사 매입 정산 |
| 3P 중개 | 수수료만 | 판매 대금에서 수수료 차감 후 셀러 지급 |
| 위탁 | 수수료 중심 | 중개 + 물류비 정산 |

미결 질문.

- 매출 인식 시점을 결제 승인으로 볼 것인가 인도 시점으로 볼 것인가
- 마감 이후 취소를 당기 차감으로 볼 것인가 차기 조정으로 볼 것인가
- 차기 이월 시 셀러 정산금이 음수가 되면 어떻게 처리하는가
- 원장을 복식부기로 갈 것인가 단순 정산 테이블로 갈 것인가

법적 지위(통신판매중개업자 고지 의무 등)와 세무 처리는 법령 원문 확인이 필요하며 추정으로 서술하지 않는다.
