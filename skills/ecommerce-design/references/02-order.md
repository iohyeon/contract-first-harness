# 주문

## 주문의 두 층

```
주문번호 하나              고객이 보는 것
  └ 내부 단위 N건          출고, 배송, 취소, 정산이 각각 흐르는 단위
```

"이 주문은 몇 개인가"라는 질문은 층을 밝히기 전까지 답할 수 없다.

분할 기준은 아래가 갈리는 지점이다.

| 갈리는 것 |
|---|
| 출고 주체 |
| 배송비 |
| 배송 상태와 운송장 |
| 취소 단위 |
| 정산 주체 |

통상 셀러 단위이며, 같은 셀러라도 출고 조건(냉장과 상온, 항공 불가, 출고지)이 다르면 한 번 더 갈린다.

1P만 운영하면 창고가 여럿일 때만 분할이 발생한다. 3P는 구조적으로 항상 발생한다.

## 결제 1 : 단위 N 비대칭

돈은 한 건으로 들어오고 물건은 여러 갈래로 나간다. 한 단위만 취소하면 결제 한 건에서 그 몫만 떼어내야 한다.

주문을 분할하는 순간 따라오는 질문.

- 한 단위만 취소할 때 결제에서 얼마를 떼는가
- 주문 전체 할인 중 그 단위의 몫은 얼마인가 (안분)
- 남은 단위가 쿠폰 최소주문금액에 미달하면 할인을 회수하는가 유지하는가

## 세 가지 그릇의 성격

| | 성격 | 가격 | 재고 |
|---|---|---|---|
| 장바구니 | 메모지 | 저장 금지, 열 때마다 재계산 | 품절이어도 삭제하지 않고 표시만 |
| 주문서 | 계산 중인 견적 | 쿠폰과 포인트로 계속 변동 | 선점 여부는 G3 정책 |
| 주문 | 서명된 계약서 | 스냅샷 고정 | 선점 확정 |

## 스냅샷 대상

| 처리 | 항목 |
|---|---|
| 복사 | 상품명, 옵션, 판매가, 할인액, 할인 부담 주체, 배송비, 셀러명, 이미지 |
| 연결만 | 상품ID, SKU ID, 셀러ID, 카탈로그ID (추적용, 금액 조회 금지) |
| 복사 안 함 | 리뷰, 현재 재고, 현재 랭킹 |

이미지를 복사하는 이유는 셀러가 사진을 교체하면 과거 주문내역의 그림이 다른 물건으로 바뀌기 때문이다.

## 멱등 처리

네트워크에서는 "미처리"와 "처리됐으나 응답 유실"을 구분할 수 없다. 버튼 비활성화는 화면단 완화책이지 해결이 아니다.

```
1번째  key = abc-123  →  처리하고 결과를 키와 함께 저장
2번째  key = abc-123  →  저장된 결과를 성공으로 반환
```

재요청에 에러를 반환하면 클라이언트가 재시도 루프에 빠진다.

## 상태 전이

```
결제대기 → 결제완료 → 상품준비중 → 배송중 → 배송완료 → 구매확정
```

역방향은 되돌리지 않고 새 상태를 앞에 붙인다.

```
결제완료 → 취소요청 → 취소완료
배송완료 → 반품요청 → 회수중 → 반품완료
```

되돌리면 어디까지 진행됐는지가 사라지고, 회수 배송비 부담 주체와 귀책 판정 근거가 없어진다.

주문 상태와 결제 상태를 분리한다. 주문 1건에 결제 시도 N건이며, 주문이 아는 것은 결제완료 여부와 결제 식별자뿐이다.
