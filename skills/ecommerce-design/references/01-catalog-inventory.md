# 카탈로그와 재고

## 속성 귀속

| 속성 | 붙는 곳 |
|---|---|
| 브랜드, 카테고리, 상세설명, 대표이미지 | SPU (상품) |
| 좋아요, 리뷰, 랭킹 | SPU |
| 판매가 | SKU (1P) / 리스팅 (3P) |
| 재고 | SKU (1P) / 리스팅 (3P) |

"상품이 몇 개"라는 문장은 SPU인지 SKU인지 수량인지 밝히기 전까지 답할 수 없다. 기획서에서 이 표현을 만나면 먼저 되묻는다.

3P에서는 카탈로그(물건)와 리스팅(셀러별 판매 조건)이 1:N이다. 1P는 1:1이라 리스팅 개념이 없다.

## 재고 수량 세 종류

```
있다        on-hand      창고 실물          실사, 발주
묶였다      allocated    출고 대기 물량
팔 수 있다  ATP          = on-hand - allocated   화면 노출, 주문 수락 판단
```

**고객 화면에는 실물재고를 띄우지 않는다.**

창고가 여럿이면 사이트별로 다시 나뉘고, 안전재고 버퍼와 입고예정이 추가된다.

## 오버셀 3원인과 처방

| 원인 | 판별 | 처방 |
|---|---|---|
| 표시 오류 | 화면에 실물재고를 노출했다 | 가용재고만 노출 |
| 동시성 | 같은 가용재고를 동시에 읽고 둘 다 통과 | 원자적 UPDATE(`qty = qty - n WHERE qty >= n`) 또는 비관적 락 |
| 동기화 지연 | 정본이 셀러 시스템 | 동기화 주기 단축, 변경 이벤트 수신, 안전재고 버퍼, 주문 직전 재확인 |

같은 "재고 1개 동시 주문"이라도 두 요청이 모두 플랫폼에서 오면 동시성, 하나가 셀러 자사몰에서 오면 동기화 지연이다. **원인을 먼저 판별하고 처방을 고른다.**

동기화 지연은 잠글 대상이 자기 DB에 없어 락으로 막히지 않는다. 확률을 낮추는 장치만 존재한다.

## 차감 시점 트레이드오프

| | 앞에서 잡는다 | 뒤에서 잡는다 |
|---|---|---|
| 오버셀 | 거의 없음 | 동시 주문 시 발생 |
| 재고 회전 | 이탈 고객이 재고를 물고 있음 | 최대 |
| 추가 비용 | 선점 TTL과 만료 회수 | 승인된 결제를 되돌림 |

## 3P 대표 리스팅 선정

최저가만으로 뽑으면 세 곳에서 깨진다.

1. 재고가 적은 리스팅이 대표가 되어 곧바로 품절 표시된다 → 재고 0은 후보 제외, 품절 시 다음 후보로 승계
2. 상품가를 낮추고 배송비로 회수한다 → 비교 기준은 고객 결제 총액
3. 출고 지연과 취소가 잦은 셀러가 대표가 된다 → 총액에 출고 속도, 취소율, 반품률, 평점을 섞은 종합 점수

## 리뷰 소유권 (정책 결정)

| 선택 | 얻는 것 | 잃는 것 |
|---|---|---|
| 물건에 귀속 | 페이지 통합이 깔끔, 신규 셀러 진입 용이 | 리뷰를 쌓은 셀러가 무임승차를 당함 |
| 셀러에 귀속 | 기여와 보상 일치 | 신규 셀러는 리뷰 0에서 시작해 판매가 어려움 |
| 물건 귀속 + 셀러별 분리 표시 | 절충 | 화면과 집계가 복잡 |

## 카탈로그 매칭

판정 수단은 바코드(GTIN 계열) > 브랜드와 모델명 규칙 > 이미지와 텍스트 유사도 순으로 신뢰도가 낮아진다.

실패 비용이 비대칭이다.

- 못 붙임: 페이지와 리뷰 분산. 고객 피해 없음
- 잘못 붙임: 다른 규격 배송. 반품비, 회수, 환불, 상담, 평점 하락

**기본값은 애매하면 붙이지 않는다.**

사은품 포함 구성은 별도 표기로 흡수하고, 구성 자체가 달라지는 세트는 분리하는 것이 통상적이다.
